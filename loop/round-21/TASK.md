# R21 — `driver-face`：笑口裝到車上之後看不到

**Wave:** W3
**Element:** `driver-face`（`BAR-VISUAL §4` #3）
**Owner:** Claude Code（`../ck-visual`，分支 `feat/visual`）
**前一輪:** R20——黏土地基接進遊戲，接線當下就發現了這個缺口

---

## 問題

R20 把 `driver-face` 當成剛性的一塊掛上車，笑口沉進引擎蓋、正面完全看不到。
違反 `CHARACTERS.md §4`（「**大圓眼 + 明確笑口**是全卡司共通識別」）與
R20 補進 `BAR-VISUAL §5.3` 的那一條：**裝到車上被擋住也算沒做到，元件圖看得到
不構成通過**。

R20 試過傾角 `-0.25`／`-0.6`／`-0.85` 三檔都無解：眼睛擺得好看笑口就埋進去，
笑口露出來（`-0.85`）就變成朝上，正面仍然看不到而且臉整個像躺著。

## 根因

**參考圖上的臉本來就不是剛性的一塊。** 回頭看
`refs/clay/characters/小紅賽車.jpg`：白色臉盤與大圓眼壓在**前擋斜面**，
笑口是另一塊黏土壓在**前保險桿**，中間隔著一整個引擎蓋的落差。

甲蟲車的車頭有兩個朝向差很多的曲面，一塊平板貼不住兩個。R20 的三次嘗試
其實是在同一個錯誤前提下移動參數，不管怎麼調都不會成立。

## 這輪做了什麼

**`src/characters/driver-face.ts`：把臉拆成兩個可獨立擺放的子群。**

`DriverFace` 多了 `eyes`（臉盤 + 大圓眼 + 眼皮）與 `mouth`（笑口 + 舌頭）兩個
`Group`。**預設仍然組成完整一張臉**掛在 `group` 底下，相對位置與 R19/R20 完全
相同——元件審查圖因此不變，這次拆分不該讓 `§3` 規範圖改變。

`setExpressionTime()` 不受影響：它改的是眼皮的 `visible`，跟階層無關，
`eyes` 被搬到哪個父節點底下都仍然有效。12fps 量化仍然只實作在這一處。

**`src/render/components/kart.ts`：兩部分各自貼在對應曲面上。**

- 眼睛：前擋斜面，維持 R20 的擺放（那一檔本來就讀得清楚）
- 笑口：鼻頭正面，落在兩顆頭燈之間，略為朝上貼合鼻頭下半段的弧度
- 鼻頭位置**從車身實際包圍盒取**，不寫死：輪廓擠出的倒角會把表面往外推，
  照輪廓座標擺會埋進殼裡——`kart-body.ts` 的頭燈踩過同一個坑

笑口比眼睛小一階（`MOUTH_SCALE` 1.5 vs `FACE_SCALE` 1.3 對應到不同基準尺寸），
第一版 1.05 太小、在正面讀起來像一個點，放大到跨滿兩顆頭燈之間才符合參考圖比例。

## 驗證

- **`§5.3` 的一眼判斷：「從正前方看，一眼認得出這台車在笑嗎?」→ 是。**
  見 `artifacts/kart-front-zoom.png`（正面與 3/4 放大）
- 元件審查圖與 R19 的差異：38940 / 1048576 位元組，**最大差值 11、平均 2.42**
  ——反鋸齒等級的浮點差異（多了一層 transform），不是造型改變。
  拆分沒有動到元件本身的樣子，如設計預期
- `§6` 全域禁令稽核：17 個材質 0 違規，self-test 4 案例仍有效
- `npm run typecheck`、`npm run build`：exit 0
- `perf-probe` 無退化：`fps_p50` 5.91（R20）→ 6.59，`draw_calls` 與
  `triangles_k` 完全相同（122 / 76.46）——只是換了掛載點，沒有新增幾何
