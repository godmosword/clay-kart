## 一、盲測從 R17 第一張表起就是破的

佔位圖把 `REF`／`OURS` 與元件名**印在圖裡**。key 檔被 gitignore 的同時，
同一份資訊從像素洩出來。

`contact-sheet.mjs` 的佔位圖 SVG 從 R17 寫出來那天就有 `${kind}` 這一行，
而 `kind` 的值就是 `'REF'` / `'OURS'`。

**洩漏是精確的，不是模糊猜測。** 一個 critic 主動把它讀到的七格逐格列出來，
拿 key 檔對照：

    r0c0 drift-sparks     ref/ours   ✓
    r1c1 skybox-lighting  ours/ref   ✓
    r2c1 ui-hud           ref/ours   ✓
    r5c1 item-boxes       ours/ref   ✓
    r2c0 water-sea        ours/ref   ✓
    r3c0 shadows-contact  ref/ours   ✓
    r4c0 kart-wheels      ours/ref   ✓

**7/7 全對。** 單邊佔位的三格更糟：佔位那半邊的標籤用排除法直接指認另一半邊。

已修（`0724e44`）：佔位圖改成不帶字的灰底，11 個佔位半邊逐位元相同。

## 二、色彩被壓成 256 色，而且只傷我們那一邊

`.png({ effort: 4 })`——sharp 的 `effort` 選項會順手把 `palette` 設成 true。
兩處都有：合成時一次，每張 tile 合成前各自再一次。

實測相異色數：

| 元件 | 修前 | 修後 | 原始元件圖 |
|---|---|---|---|
| track-barriers | **24** | 1475 | 1475 |
| foliage | **62** | 4025 | 4025 |

黏土算繪的全部重點是壓痕的細微明暗。壓成二十幾色之後只能靠**抖動**近似漸層，
而抖動看起來就是 `§6` 禁止的「程序化雜訊當表面細節」。

**三輪的扣分理由直接證實了這件事：**

- run1：「橘段表面是橘/黃逐點交錯的**抖動雜訊**（§6 明文禁）」
- run1：「（foliage）整面是**均勻抖動雜訊**（§6）」
- run3：「橘段表面是紅／黃**亂數點噪**，正中 §6」
- run3：「（kart-body）全車覆蓋**均勻點噪**而非壓棒渦紋」

不對稱在於參考半邊是高對比高飽和的實拍照片，量化後幾乎無損。
**這張表系統性地摧毀了它自己要評的那個性質，而且只摧毀一邊。**

已修（`0724e44`），並加 `assertNotPalettised()` 讀回 IHDR 擋掉調色盤輸出。

## 三、比這兩項更深的問題：這個盲測本來就不可能成立

修掉標籤與量化之後，**盲測仍然不成立**。三個 critic 都各自指出了原因：

> 有內容的半邊分成兩類：一類是黏土實拍風的場景近照（有景深、有彩色背景、
> 每張打光不同），另一類是灰底四視角的元件渲染圖。

我們那半邊永遠是 `#8a8a8a` 灰底上的四視角規範圖，參考那半邊永遠是實拍微距
照片。**只看構圖就 100% 分得出來**，一個標籤都不需要。

而且它同時讓比較失去意義：`§5.0` 的決定性判準（指紋、壓棒痕、接縫）**只有在
微距下才解析得出來**，我們卻把四個物件塞進 1/8 畫面去跟微距照比拼表面工藝。
`§3` 明文「所有元件圖必須在同一組條件下渲染，否則評分不可比」——五個有內容
的格子**沒有一格滿足**。

seed-17 洗牌、gitignore key 檔、去識別化標準——這一整套是為了保護一個
**從來沒有成立過**的盲測。這是本輪最重要的發現，也是唯一沒有修法的一項。

## 四、`§6` 與參考素材互斥

三個 critic 各自用線性空間飽和度掃過每個半邊，數字互相吻合：

| 半邊 | 超過 `§6` 上限 0.92 的像素比例 |
|---|---|
| 實拍參考半邊（driver-face） | 43% |
| 實拍參考半邊（foliage） | 41% |
| 實拍參考半邊（kart-body） | 36% |
| **我們所有的算繪半邊** | **0.00–0.05%** |

天空 `#0878c8` 線性飽和度 0.99，車紅 `#e83828` 是 0.94。純黑也一樣：
`track-barriers` 的參考半邊有 7.6% 的像素亮度 ≤16，最暗 `(3,3,2)`——
那是一整片柏油路，而 `§5.4` 明文「柏油在黏土世界裡沒有出處」。

**材質與手感分數最高的那幾張，同時是唯一大面積踩到 `§6` 的。**
這是 R28（`§5.5` vs `§6`）、R30（`§5.6` vs 黃金樣本）之後的第三次同形狀缺陷。

## 五、`§5.6` 的兩個參考素材彼此矛盾

run1 指出：foliage 的參考半邊，樹冠明確就是**幾顆大團塊疊起來**，反而是我們
的算繪在做「交疊葉瓣」——如果那張出自 `refs/clay/`，R30 的修訂方向是反的。

我裁出那半邊親眼看了，**run1 是對的**。但兩張參考圖是不同來源：

- `refs/clay/car-park.png`（黃金樣本）→ 一顆圓穹壓滿葉瓣（我 R30 看的）
- `refs/clay/characters/安安救護車.jpg`（`§7.1` 指定的 foliage 參考半邊）
  → 幾顆球疊起來

**兩份參考素材對「黏土樹長什麼樣」的答案不一樣。** `§0` 說黃金樣本是最高
權威，照那句話 R30 的修訂站得住；但 critic 比的是配對表裡的那一張。
`§5.6` 原文寫「團塊堆疊」大概正是照著 `安安救護車.jpg` 寫的，只是把來源
誤記成黃金樣本。

需要裁決：是讓 `§5.6` 容納兩種形態（黃金樣本的樹是背景小道具、
`安安救護車.jpg` 的是前景主體，尺度不同做法不同），還是換掉配對素材。
